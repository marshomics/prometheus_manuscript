## Verified correct, no change

- `bh_correction` (results_registry.py:54-76) already excluded missing p-values from m and
  matched BH; it is kept as an alias of `p_adjust(..., "BH")` and checked against R's `p.adjust`.
- `plot_validation_tree` rule: its flags (`--tree --labels --catalog --plot-prefix`) match
  `plot_validation_tree.R`'s `make_option`s (frozen CLI, leaf 1.1.2); only the prefix param is
  now derived from the output.
- `species_tree.treefile` is the ROOTED tree (scaffolds.smk: `root_tree.py --out-tree
  {output.tree}`; the revised rule adds a `full_tree` output but keeps this path).
- `viral_summary.tsv` has one row per sample genome with 0 for no provirus (aggregate_viral.py
  iterates the samples), so a tip without a viral row really is "no data".
- Contract v2 item 6 (tier presence rule): synthesis computes no tier-based binary response. The
  master tree paints the best validated tier itself (A/B/C/absent/no data), so a B-only genome
  is shown as B, never as an absence (rings test: G2; circular test: all B tips). The registry
  treats a producer `tier_set` other than the primary set as a sensitivity row.
- End-to-end with real producers (run 2026-10-30, read-only): the revised association_tests.R
  wrote the six labels naive_glm, naive_fisher, phyloglm_methanogen, phyloglm_confounders,
  fitPagel, D_statistic, and the pristine ancestral_states.R wrote its eight metrics. The strict
  registry tagged the headline and the enrichment test confirmatory, with association BH m = 4
  (headline p 0.01558 -> p_adj 0.0623).
- Pinned stack: under ggplot2 3.5.1 / ggnewscale 0.4.10 / ggtree 3.10.0 / patchwork 1.2.0 the
  master tree renders and its ring values are byte-identical to the prom-r run
  (`test_master_tree_pinned_rstats_stack`). Note: without the `r-patchwork=1.2.0` pin a solve
  picks patchwork >= 1.3, which imports `ggplot2::is_ggplot` (ggplot2 >= 3.5.2), and ggtree then
  fails to load. rstats.yaml must keep that pin.
